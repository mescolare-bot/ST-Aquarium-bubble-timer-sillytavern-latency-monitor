## 当前未完成

### 1. 用户尚未最终确认最新线上 UI 是否全部符合预期

虽然最新版本化文件已经重新部署，但用户还没有对修正后的线上状态做最终验收。

建议下一个账号先做一次“用户视角验收”，重点确认：

1. 悬浮球是否可按住拖动
2. 右上角三个按钮是否真的变小
3. 主题文案是否显示为 `主题：日 / 夜 / 跟随酒馆模式`
4. 全部历史详情默认是否不再提前露出勾选图标

### 2. 历史删除流程还没有完全收成用户最初想要的最终形态

用户之前明确希望：

- 先有高一级的“删除历史记录”入口
- 进入删除模式后再显示勾选与批量操作
- 最后尽量收成统一确认链

目前已完成“删除模式入口”和“默认不露勾选”，但代码里仍保留了旧的删除范围分支逻辑：

- `删除勾选项里的全部记录`
- `删除勾选项里的正常记录`

这部分是否要继续收口成单一确认链，需要下一个账号接着和用户确认或继续改。

### 3. iOS / 手机端下一版本适配还没有正式开始

聊天里已经完成了方向确认，但还没有进入代码实现。

已确认的大方向是：

- `iOS 全屏 drawer + 二级页 + bottom sheet`

这属于后续版本，不是当前已完成内容。

### 4. 未知拓展调用的“等待区补名 + 规则沉淀”机制尚未开始

用户已经确认希望补一套更通用的拓展分桶方案，而不是继续给单个拓展写死后端指纹。

当前共识方向：

1. 未识别的拓展调用先进入“等待区”
2. 用户可手动输入拓展名字修正记录
3. 不只是改当前一条，还要支持把这次人工命名沉淀为后续可复用的识别规则
4. 规则应尽量依赖稳定特征，而不是模型名，这样后续即使切换调用模型仍可识别

这部分目前还没有进入实现，需要后续单独设计：

- 规则库存储结构
- 规则匹配优先级
- “仅修正当前记录”与“保存为识别规则”的交互
- 与显式 `request_purpose / request_plugin` 上报链路的关系

详细状态见：

### 6. 长时间卡住或已确认异常的生成，已进入“待部署实测”阶段

这一块本地代码已经按最新收口方向改完，但还没完成真实部署环境验证。

当前方案已经收口为：

1. 不做“仅因等待太久”就触发的提醒
2. 只有在后端明确异常后才介入
3. 用户点开后再弹“是否终止：是 / 否”
4. 终止时优先走酒馆原生停止
5. 若仍卡住，则继续走监控接管请求的强制 `abort`
6. 强制切断后再补一次 `Escape`
7. 手机端悬浮按钮改为：短按进监控，长按弹“强行终止当前生成？”确认
8. 所有选择弹窗补上“点空白处关闭”

这部分的待部署实测清单见：

- `backend-monitor-minimal/pending-live-verification-batch.md`

## 当前风险项

### 高风险但已处理的事项

1. 版本化前端文件与主文件脱节
   - 已发生过一次
   - 表现是：用户刷新了，但什么都没变
   - 根因：改了 `index.js/style.css`，但线上真实加载的是旧版 `index.20260730.js/style.20260730.css`
   - 现状：已改为新的 `index.20260730.1818.js/style.20260730.1818.css`

2. SSH 目标机器混淆
   - 旧 IP：`<OLD_HOST>`
   - 当前正确 IP：`<SSH_HOST>`
   - 后续不要再把旧 IP 当作当前生产机

3. 登录用户混淆
   - `root` 当前不能直接用本机密钥登录
   - 实际可用的是 `<SSH_USER>@<SSH_HOST>`
   - 需要通过 `sudo` 操作正式目录和服务

   - 文件已确认上线
