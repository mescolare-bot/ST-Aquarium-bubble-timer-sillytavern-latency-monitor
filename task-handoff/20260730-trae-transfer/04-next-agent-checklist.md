# 新账号接手建议顺序

## 接手后先做什么

1. 先看 `00-README.md`
2. 再看 `01-current-status-and-pending.md`
3. 部署或查线上前，必须看 `02-server-and-deploy.md`
4. 动手改代码前，先看 `03-critical-pitfalls.md`

## 第一次接手的建议动作

### A. 先确认本地环境

检查这些文件是否都在：

- `manifest.json`
- `index.js`
- `style.css`
- `index.20260730.1818.js`
- `style.20260730.1818.css`
- `backend-monitor-minimal/...`

### B. 先确认线上版本

确认线上 `manifest.json` 是否仍指向：

- `index.20260730.1818.js`
- `style.20260730.1818.css`

### C. 先做一次用户视角验收

建议优先请用户确认这几项：

1. 悬浮球是否能拖动
2. 右上角三按钮是否缩小
3. 主题文案是否正确
4. 全部历史详情默认是否不露勾选

## 当前最值得优先继续的工作

### 1. 收尾历史删除流程

当前已经有删除模式入口，但是否还要继续把：

- “全部记录 / 正常记录” 两段式确认

收口成用户更早要求的单一确认链，需要继续推进。

### 2. 补做“异常生成中止链”的部署实测

这一块本地代码已经完成，当前不再是“待实现”，而是“待部署实测”。

当前方案已经收口为：

1. 不做“仅因等待太久”就触发的提醒
2. 只在后端明确异常后才介入
3. 点开后再弹“是否终止：是 / 否”
4. 终止时优先走酒馆原生停止
5. 若仍卡住，则继续走监控接管请求的强制 `abort`
6. 强制切断后再补一次 `Escape`
7. 手机端悬浮按钮改为：短按进监控，长按弹“强行终止当前生成？”确认
8. 所有选择弹窗补上“点空白处关闭”

部署恢复后，优先按这份清单补测：

- `backend-monitor-minimal/pending-live-verification-batch.md`

### 3. 开始 iOS / 手机端新版本

方向已经在聊天里确认过：

- `iOS 全屏 drawer + 二级页 + bottom sheet`

这部分属于真正还没开工的下一版本。

### 4. 做一次完整线上回归检查

建议按以下顺序测：

1. 打开魔棒菜单
2. 打开插件页
3. 切换主题
4. 悬浮隐藏 / 恢复 / 拖动悬浮球
5. 打开全部历史详情
6. 进入删除模式
7. 删除流程确认链

## 不建议新账号上来就做的事

1. 不要一上来就重新整理整个仓库结构
2. 不要先改服务器权限模型
3. 不要先删旧版本文件
4. 不要先重写部署脚本

这些都容易把现在线上能跑的状态打乱。
