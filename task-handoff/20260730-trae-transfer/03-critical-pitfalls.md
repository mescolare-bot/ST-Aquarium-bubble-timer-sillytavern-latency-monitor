# 关键坑点与注意事项

## 1. 最大坑：版本化前端文件和主文件脱节

这是本项目交接里最重要的一条。

### 现象

- 本地已经改了 `index.js` 和 `style.css`
- 也已经部署了
- 用户刷新后却说“没有一个对”

### 根因

线上 `manifest.json` 实际加载的是：

- `index.20260730.js`
- `style.20260730.css`

而不是根目录的：

- `index.js`
- `style.css`

所以只覆盖主文件是没用的。

### 正确做法

每次前端改动后，至少要同步这三层：

1. `index.js` / `style.css`
2. 新的版本化文件
3. `manifest.json` 指向新的版本化文件

### 当前已用的新版本文件

- `index.20260730.1818.js`
- `style.20260730.1818.css`

## 2. 部署前必须确认服务器身份

之前之所以出现 SSH 指纹异常，是因为连错了机器。

### 已确认事实

- 旧 IP：`<OLD_HOST>`
- 当前正确 IP：`<SSH_HOST>`

### 经验结论

当 SSH 指纹和预期不一致时，不要先怀疑用户刷新没刷新，也不要立刻覆盖 `known_hosts`，先确认是不是 IP 就错了。

## 3. SSH 登录账户不是 root

这次实际能登录的是：

- `<SSH_USER>@<SSH_HOST>`

不是：

- `root@<SSH_HOST>`

实际部署时要：

1. 用 `admin` 登录
2. 用 `sudo` 写入 `/root/SillyTavern/...`

## 4. 用户对部署权限非常敏感

这是硬规则。

### 必须遵守

- 没有用户明确说“部署”，就不能改线上
- 没有用户明确允许，就不要主动重启服务

### 沟通方式

最好把“本地已完成”和“是否部署”分开说。

## 5. UI 风格约束非常明确

用户已经多次反复确认过这些原则，后续不要再偏掉：

1. 严禁渐变色
2. 严禁模糊/柔光/backdrop-filter
3. 非悬浮球不要做半透明模式
4. 日间主题要和异常黄色警报区明显区分
5. 顶部按钮尺寸、图标风格要统一
6. Tooltip 要极简

## 6. 当前工作区不是干净树

不要做这些操作：

- `git reset --hard`
- `git checkout --`
- 无差别清理未跟踪文件

因为当前工作区同时包含：

- 已部署相关文件
- 版本化前端文件
- 未提交的本地记录文件
- 后端准备文件

## 7. 做完但仍需用户验证的内容不要擅自判定“彻底完成”

例如：

- 悬浮球拖动
- 历史详情删除模式
- 新主题颜色
- 顶部按钮缩小

这些就算代码和线上文件都对了，也仍然要以用户视觉验收为准。
